# យុទ្ធសាស្រ្តបណ្តុះបណ្តាល Deep Learning

ដោយសារបណ្ដាញប្រព័ន្ធសរសៃប្រសាទកាន់តែជ្រៅ ការបណ្តុះបណ្តាលរបស់ពួកវាកាន់តែមានកម្រិតដ៏បញ្ហា។ បញ្ហាសំខាន់មួយគឺអ្វីដែលហៅថា [ស្លាបក្រាំងគន្លងចុះ](https://en.wikipedia.org/wiki/Vanishing_gradient_problem) ឬ [ស្លាបក្រាំងផ្ទុះ](https://deepai.org/machine-learning-glossary-and-terms/exploding-gradient-problem#:~:text=Exploding%20gradients%20are%20a%20problem,updates%20are%20small%20and%20controlled.)។ [អត្ថបទនេះ](https://towardsdatascience.com/the-vanishing-exploding-gradient-problem-in-deep-neural-networks-191358470c11) ផ្តល់ការណែនាំល្អអំពីបញ្ហាទាំងនេះ។

ដើម្បីធ្វើឱ្យការបណ្តុះបណ្តាលបណ្ដាញជ្រៅមានប្រសិទ្ធភាពល្អប្រសើរជាងមុន មានបច្ចេកទេសមួយចំនួនដែលអាចប្រើប្រាស់បាន។

## ការរក្សាតម្លៃនៅក្នុងចន្លោះសមរម្យ

ដើម្បីធ្វើឱ្យការគណនាទិន្នន័យគណនាប្រហែលមើលទៅមានស្ថិរភាព យើងចង់ធានាថាតម្លៃទាំងអស់ក្នុងបណ្ដាញប្រព័ន្ធសរសៃប្រសាទគឺនៅក្នុងលំហដែលសមនឹងគ្នា ជាទូទៅគឺ [-1..1] ឬ [0..1]។ វាមិនមែនជាតម្រូវការដឹកជញ្ជូនខ្លាំងណាស់ទេ ប៉ុន្តែការគណនាទ្រង់ទ្រាយកំណត់ជាបណ្តាញបន្ទាត់នេះមានទេពកោសល្យដែលថាតម្លៃមានធំតូចខុសគ្នា មិនអាចគ្រប់គ្រងបានជាក់លាក់រួចជាមួយគ្នា។ ឧទាហរណ៍បើយើងបូក 10<sup>-10</sup> និង 10<sup>10</sup> ចំណុចតូចនឹងត្រូវបាន "បម្លែង" ទៅលំដាប់ដូចគ្នានឹងតម្លៃធំធេង ហើយភាពត្រឹមត្រូវនៃ mantissa នឹងបាត់បង់។

មូលដ្ឋានសកម្មភាពភាគច្រើនមានភាពមិនប៉ុនប៉ងនៅជុំវិញ [-1..1] ហើយដូច្នេះវាមានសមត្ថភាពក្នុងការបង្ហាញប្រភេទទិន្នន័យទាំងអស់ទៅចន្លោះ [-1..1] ឬ [0..1]។

## ការចាប់ផ្តើមចំណាត់ថ្នាក់បន្ទះ

ដូចដែលយើងចង់ឲ្យតម្លៃនៅក្នុងលំហដូចគ្នាបន្ទាប់ពីកាត់ដេគ្នាតាមស្រទាប់បណ្ដាញ ដូច្នេះវាមានសារៈសំខាន់ក្នុងការចាប់ផ្តើមបន្ទះនៅលទ្ធភាពណាមួយក្នុងការរក្សាសមាមាត្រតម្លៃ។

ចំណែកបង់ចំណែកធម្មតា **N(0,1)** មិនមែនជាគំនិតល្អទេ ព្រោះបើយើងមាន *n* ចំណូល, ស្តង់ដារប្រសិទ្ធភាពនៃលទ្ធផលនឹងកើតមានជា *&radic;n* ហើយតម្លៃប្រហែលនឹងកន្លងចេញពីចន្លោះ [0..1]។

ការចាប់ផ្តើមបន្ទះខាងក្រោមត្រូវបានប្រើជាញឹកញាប់៖

 * ពហុធម្មតា -- `uniform`
 * **N(0,1/n)** -- `gaussian`
 * **N(0,1/&radic;n_in)** ប្រាកដថាថៃមិនមួយចំនូលដែលមានមធ្យមសូន្យ និងស្តង់ដារប្រសិទ្ធភាព 1 នឹងរក្សាមធ្យម/ស្តង់ដារប្រសិទ្ធភាពដដែល
 * **N(0,&radic;2/(n_in+n_out))** -- ហៅថា **Xavier initialization** (`glorot`), វាជួយរក្សាសញ្ញានៅក្នុងលំហក្នុងការបញ្ជូនទៅមុខ និងត្រឡប់ក្រោយ

## ការបញ្ញើតផ្ទះក្រោមចេញជាបណ្ណាល័យ Batch Normalization

ទោះបីជាមានការចាប់ផ្តើមបន្ទះបញ្ញើតល្អក៏ដោយ បន្ទះអាចក្លាយជាធំឬតូចតាមចៃដន្យនៅពេលបណ្តុះបណ្តាល ហើយវានឹងផ្តល់សញ្ញាដោយកន្លងពីលំហត្រឹមត្រូវ។ យើងអាចយកសញ្ញាត្រឡប់តាមរយៈបច្ចេកទេស **normalization** មួយ។ ខណៈដែលមានច្រើន (ការបញ្ញើតរន្ធយកទំងន់, បញ្ញើតស្រទាប់) វាជាមួយជាច្រើនត្រូវបានប្រើសម្រាប់ Batch Normalization។

គំនិតនៃ **batch normalization** គឺការយកតម្លៃទាំងអស់ក្នុងមីនីបេជចេញ ហើយអនុវត្តបញ្ញើត (ដូចជា ដកមធ្យម ហើយបែងចែកដោយស្តង់ដារប្រសិទ្ធភាព) ដោយផ្អែកលើតម្លៃទាំងនោះ។ វាត្រូវបានអនុវត្តជាស្រទាប់បណ្ដាញដែលធ្វើបញ្ញើតបន្ទាប់ពីអនុវត្តទំងន់ ប៉ុន្តាមុនមុខងារបញ្ញើត។ ជាលទ្ធផល យើងត្រូវបានប្រហែលឃើញភាពត្រឹមត្រូវខ្ពស់ និងការបណ្តុះបណ្តាលរហ័ស។

នៅទីនេះមាន [អត្ថបទដើម](https://arxiv.org/pdf/1502.03167.pdf) ស្តីពី batch normalization, [ការពន្យល់លើ Wikipedia](https://en.wikipedia.org/wiki/Batch_normalization), និង [អត្ថបទប្លក់ណែនាំល្អមួយ](https://towardsdatascience.com/batch-normalization-in-3-levels-of-understanding-14c2da90a338) (ហើយមួយ [ជារុស្ស៊ី](https://habrahabr.ru/post/309302/))។

## Dropout

**Dropout** គឺជាបច្ចេកទេសមួយដែលដកចេញភាគរយនៃណឺរុនចៃដន្យនៅពេលបណ្តុះបណ្តាល។ វាត្រូវបានអនុវត្តជាស្រទាប់ដែលមានប៉ារ៉ាម៉ែត្រមួយ (ភាគរយណឺរុនដើម្បីដកចេញ ជាទូទៅ 10%-50%) ហើយនៅពេលបណ្តុះ បណ្តុះបណ្តាលវាត្រូវរក្សាតម្លៃត្រិចចៃដន្យនៃវ៉ិចទ័រចូល មុនបញ្ជូនវាទៅស្រទាប់បន្ទាប់។

ទោះបីវាហាក់ដូចជាគំនិតចម្លែក ក៏អ្នកអាចឃើញប្រសិទ្ធិភាពរបស់ dropout លើកម្មវិធីចាត់ថ្នាក់ឃ្លីដោយ MNIST នៅក្នុងកំណត់ត្រា [`Dropout.ipynb`](Dropout.ipynb)។ វាធ្វើឱ្យបណ្តុះបណ្តាលរហ័ស ហើយអាចឲ្យយើងទទួលបានភាពត្រឹមត្រូវខ្ពស់ជាងមុនក្នុងចំនួន epoch តិចជាង។

ប៉ះពាល់នេះអាចត្រូវបានពន្យល់តាមរយៈរបៀបចំនួនមួយ៖

 * វាអាចត្រូវបានចាត់ទុកជាធាតុខកចិត្តចៃដន្យសម្រាប់ម៉ូដេល ដែលយកការប្រសើរចេញពីព្រំដែនមូលដ្ឋាន
 * វាអាចត្រូវបានចាត់ទុកជាការសរុបម៉ូដេលដូចជា *ការបូកបន្ថែមម៉ូឌែលគ្មានការពង្រីក* ព្រោះយើងអាចនិយាយថា កំឡុងពេល dropout យើងកំពុងបណ្តុះម៉ូឌែលខុសគ្នាបន្តិច

> *មនុស្សខ្លះនិយាយថា នៅពេលមនុស្សទៅលក់ថ្នាំពេជ្រអូនឆ្លងស្រា ពេលរៀនអ្វីមួយ គាត់នឹងចងចាំបានល្អជាងពេលពូកែល្បី ព្រោះខួរក្បាលនាំមកនូវណឺរុនខូចមួយចំនួន ព្យាយាមកែលម្អសម្រាប់យល់អត្ថន័យ។ យើងមិនដែលសាកល្បងដោយខ្លួនឯងថាវាត្រូវឬមិនត្រូវទេ*។

## ការពារ overfitting

រឿងសំខាន់មួយនៃ deep learning គឺអាចទប់ស្កាត់ [overfitting](../../3-NeuralNetworks/05-Frameworks/Overfitting.md)។ ទោះបីជាគម្រោងម៉ូឌែលប្រព័ន្ធសរសៃប្រសាទមានកម្លាំងខ្លាំង ក៏យើងគួរតែតុល្យភាពចំនួនប៉ារ៉ាម៉ែត្រម៉ូឌែលជាមួយចំនួនឧទាហរណ៍បណ្ដុះបណ្ដាល។

> សូមធ្វើឱ្យប្រាកដថាអ្នកយល់ពី​គំនិត [overfitting](../../3-NeuralNetworks/05-Frameworks/Overfitting.md) ដែលយើងបានណែនាំមុននេះ!

មានរបៀបនានា ដើម្បីទប់ស្កាត់ overfitting:

 * ការឈប់ដំណើរការពេលឆាប់ៗ -- ត្រួតពិនិត្យកំហុសមួយលើ validation set ជាបន្តបន្ទាប់ ហើយបញ្ឈប់បណ្តុះបណ្តាលនៅពេលកំហុស validation ចាប់ផ្ដើមកើនឡើង។
 * ការបន្ថែមទំងន់ជាក់លាក់ / តុល្យភាព -- បន្ថែមជើងសំពាធបន្ថែមទៅលើ loss function សម្រាប់តម្លៃដាច់ខាតខ្ពស់នៃទំងន់ ដែលទប់ស្កាត់ម៉ូឌែលធ្វើឲ្យលទ្ធផលមិនមានស្ថិរភាពខ្លាំង
 * ការសរុបទិន្នផលម៉ូឌែល -- បណ្តុះបណ្ដាលម៉ូឌែលជាច្រើន ហើយបន្ទាប់មកសរុបលទ្ធផល។ វាជួយកាត់បន្ថយការប្រែប្រួល។
 * Dropout (ការសរុបម៉ូឌែលមិនបញ្ចាក់)

## អ្នកបង្កើត / អាល់គរីធម៍បណ្តុះបណ្ដាល

មុខវិជ្ជាសំខាន់មួយទៀតនៃការបណ្តុះបណ្តាលគឺការជ្រើសរើសអាល់គរីធម៍ល្អ។ ខណៈដែល **gradient descent** ត្រូវបានគេប្រើជាច្រើនទ្ទាំង វាអាចយឺត ឬបង្កភាពបញ្ហាផ្សេងៗ។

### Momentum

ក្នុង **momentum SGD**, យើងរក្សាផ្នែកនៃក្រាឌីយង់ពីជំហានមុន។ វាដូចជាការផ្លាស់ទីមានអ៊ីណែរ៉ា ហើយបើមានការប្រហែលចាំបាច់ ក្នុងទិសផ្សេងទៀត យើងមិនប្តូរយ៉ាងភ្លាមៗទេ ប៉ុន្តែរក្សា​ផ្នែកនៃចលនាមុនដូចគ្នា។ នៅទីនេះយើងបញ្ចូលវ៉ិចទ័រ v មួយសម្រាប់សំដៅ *ល្បឿន*៖

### Adam, Adagrad, ល។

ទម្រង់ដំណោះស្រាយមួយសម្រាប់បញ្ហានេះគឺប្រើតែទិសដៅនៃក្រាឌីយង់ក្នុងសមីការ ហើយមិនគិតពីតម្លៃដាច់ខាតឡើយ, និយាយគឺ

> **Adam** ត្រូវបានចាត់ថាជាអាល់គរីធម៍មានប្រសិទ្ធភាពខ្ពស់សម្រាប់កម្មវិធីជាច្រើន ដូច្នេះបើអ្នកមិនប្រាកដថាតើគួរប្រើអ្វី - ការប្រើប្រាស់ Adam គឺល្អ។

### ការកាត់បន្ថយក្រាឌីយង់

ការកាត់បន្ថយក្រាឌីយង់ជារបៀបបន្ថែមលើគំនិតខាងលើ។ នៅពេល ||&nabla;&lagran;|| &le; &theta; យើងគិតថាក្រាឌីយង់ដើមជាការជ្រើសរើសក្នុងការបូកបន្ថយទំងន់ ហើយនៅពេល ||&nabla;&lagran;|| > &theta; - យើងបែងចែកក្រាឌីយង់ដោយស្តង់ដាររបស់វា។ នៅទីនេះ &theta; ជាប៉ារ៉ាម៉ែត្រ ខាងឡើយភាគច្រើនយើងអាចយក &theta;=1 ឬ &theta;=10។

### ការកាប់ដើមអត្រាបណ្ដុះបណ្ដាល

ការជោគជ័យក្នុងការបណ្តុះបណ្តាលភាគច្រើនមានឥទ្ធិពលលើប៉ារ៉ាម៉ែត្រអត្រាបណ្ដុះបណ្ដាល &eta;។ វាជាការសម្របសម្រួលលោកល្អដែលតម្លៃធំៗនៃ &eta; នាំឲ្យបណ្តុះបណ្តាលរហ័ស ដែលជារឿងដែលយើងចង់បានកាលពីដើមបណ្ដុះបណ្ដាល ហើយបន្ទាប់មកតម្លៃតិចនៃ &eta; អនុញ្ញាតឲ្យដំណើរការត្រួតពិនិត្យបណ្តាញបានល្អប្រសើរ។ ដូច្នេះភាគច្រើនយើងចង់បន្ថយ &eta; ក្នុងដំណើរការបណ្តុះបណ្ដាល។

នេះអាចធ្វើបានដោយគុណ &eta; ជាមួយចំនួនមួយ (ឧ. 0.98) បន្ទាប់ពីជំនាន់រៀងៗខ្លួននៃបណ្តុះបណ្ដាល ឬប្រើបច្ចេកទេស **learning rate schedule** ពិបាកជាង។
